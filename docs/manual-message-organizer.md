# 主动消息整理设计

日期：2026-09-16。状态：已实施。

## 产品边界

产品保留两条独立链路：

1. **消息整理**：用户发起、一次性执行、只读不发送。页面打开和页面轮询不操作微信。
2. **自动回复**：只对用户明确启用的联系人或群组持续扫描，继续使用既有规则、去重、复读和发送回执。

消息整理不是实时收件箱，也不承诺覆盖全部微信历史。它用于用户在需要时快速完成一次任务：总结最近消息、找出需要回复的会话、提取待办，或执行一条自然语言要求。

## 交互

「消息」首屏由四张操作卡片和一个输入框组成：

- 整理最近消息；
- 找出需要回复的；
- 提取待办；
- 看看有没有遗漏；
- 用户也可直接输入任意具体要求。

页面另提供「只刷新会话列表」。该操作只读取微信左侧当前可见列表，不打开聊天、不清未读红点。整理任务可按用户要求打开必要会话，最多读取 5 个；遇到微信正在使用或会话不可读时跳过，不进入后台重试。

整理结果直接显示在当前页面。符合 `- [ ]` 形式的行动项可以一次加入「今天要做的」。过去成功整理过的会话保留在「最近整理」，供用户回看、继续生成草稿或记待办。

## 不变量

- `GET /message-agent/api/message-center` 只能读取本地状态和 Worker 缓存，不能触发微信扫描或正文读取。
- 只有 `POST /message-agent/api/message-center/refresh` 和用户主动整理、读取、拟稿、提问动作可以访问微信。
- Worker 的普通循环只为已启用的自动回复规则调用 `list_conversations`。
- 消息整理不得发送微信消息，不得创建后台重试，不得在任务结束后继续等待新消息。
- 旧版本保存的 `observe_enabled` 和 `read_bodies` 不能重新开启后台消息读取。

## 验收

- 没有启用自动回复规则时，Worker 连续运行不会扫描或打开微信。
- 打开「消息」并停留 30 分钟，微信会话不会发生切换。
- 页面轮询不会调用 `observe_latest`。
- 点击操作卡片或提交输入后才允许读取；一次任务结束后调用停止。
- 自动回复规则仍能独立发现新消息、生成决策并按原状态机发送。
